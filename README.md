# SadRoger — тестовое задание «Ветер и выход за границу морской локации»

[Играть в браузере](https://kirvas-dev.github.io/SadRoger-TestTask/)

Unity 6.5 (6000.5.0f1), URP. Стек: VContainer (DI), R3 (реактивные модели), UniTask, Cinemachine, TextMesh Pro.

## Запуск

1. Открыть папку `SadRoger/` в Unity Hub (версия 6000.5.0f1).
2. Открыть сцену `Assets/_Project/Scenes/Core.unity` или `Bootstrap.unity` и нажать Play: при старте из любой сцены загружается Bootstrap, а он догружает Core.
3. Управление: **W / S** — ход вперёд / назад, **A / D** — поворот.
4. Ветер и погода меняются **в Play Mode через Inspector**:
   - объект `Wind` → компонент `WindInspectorInput`: `Direction` (0–360°, откуда дует ветер) и `Strength` (0–1);
   - объект `Weather` → компонент `WeatherInspectorInput`: `State` (Clear / Rain / Storm / Fog).
5. Те же параметры дублируются в UI:
   - в HUD ветра слева сверху есть слайдеры «Направление» и «Сила»;
   - в HUD погоды справа сверху есть кнопки Ясно / Дождь / Шторм / Туман.

   UI и Inspector — равноправные источники ввода. Слайдеры следуют за моделью, поэтому правка в Inspector сразу двигает их. Поле Inspector после правки в UI не обновляется, но следующая правка в нём снова применяется. Слайдер «Сила» задаёт базовую силу, а строка «Сила» показывает итоговую силу после погодного множителя.
6. Тесты: `Window → General → Test Runner → EditMode → Run All` (32 теста).

## Что сделано

**Часть 1. Ветер**
- Направление 0–360° (нормализуется), сила 0–1. Направление — откуда дует ветер, как принято в метеорологии; 0° — мировая ось +Z, угол растёт по часовой стрелке (как `transform.eulerAngles.y`).
- HUD слева сверху: направление, сила, относительный угол и стрелка-индикатор.
- Относительный угол — `ветер − курс`, со знаком, в диапазоне (−180°, 180°]: 0° — ветер в нос, «+» — с правого борта, «−» — с левого.
- Индикатор привязан к кораблю: под стрелкой полупрозрачный силуэт корабля носом вверх, стрелка показывает, куда дует ветер. При повороте корабля стрелка и угол обновляются реактивно.

**Часть 2. Граница локации**
- Круг: центр — позиция объекта с `LocationBoundaryCenter` в сцене, радиус в `LocationBoundaryConfig`; на воде нарисован красным кольцом.
- Машина состояний `Inside → Leaving (1 с) → Warning (5 с отсчёт) → Exited`:
  - возврат внутрь из любого состояния → `Inside`: таймер сброшен, сообщение скрыто;
  - переход в `Exited` поднимает событие `ILocationBoundaryEvents.LocationExited` (это `OnLocationExit`) ровно один раз. У события два независимых подписчика: `LocationExitLogger` пишет `Debug.Log("Location exited")`, а `LocationExitNoticePresenter` показывает плашку «Вы покинули игровую область», которая скрывается, когда корабль возвращается в зону;
  - после возврата следующий выход запускает новый полный цикл.
- **Параллельные таймеры невозможны по построению:** таймер — одно поле `_outsideTime` в `LocationBoundaryService`, которое тикает в общем игровом цикле. Нет корутин, `Invoke` и `UniTask.Delay`, которые пришлось бы отменять.

**Дополнительно. Weather Preset Resolver**
- `WeatherState`: Clear / Rain / Storm / Fog. Для каждого состояния — отдельный ассет `WeatherPreset_*` (`intensity`, `fogDensity`, `windMultiplier`).
- `WeatherConfig` сопоставляет состояния и пресеты. `WeatherService.SetState` находит пресет, кладёт его в модель и передаёт `windMultiplier` ветру.
- Сила ветра = `clamp01(base × windMultiplier)`. Туман включается через `RenderSettings`, в HUD справа видны состояние и интенсивность.

## Структура решения

Код лежит в `SadRoger/Assets/_Project/Scripts/`. Каждая сборка (asmdef) отвечает за свой слой:

| Сборка / папка | Что внутри |
|---|---|
| `Core/Gameplay/{Ship, Wind, Weather, LocationBoundary, Navigation}` | Чистый C# без `UnityEngine` (`noEngineReferences`): модели (`ReactiveProperty`), сервисы с правилами, порты в `Api/` |
| `Core/Input/{Ship, Wind, Weather}` | InputHandler'ы: порт ввода → команда сервиса |
| `Input/` | `ShipKeyboardInput` — адаптер Input System (W/A/S/D) |
| `ViewComponents/{Ship, Wind, Weather, LocationBoundary}` | MonoBehaviour'ы сцены: View корабля и тумана, Inspector-ввод, кольцо границы, конфиги (ScriptableObject) |
| `UI/{WindHud, WeatherHud, BoundaryWarning, LocationExitNotice}` | Экраны MVP: пассивный View + Presenter, который подписан на модели. Клики по кнопкам погоды идут из View в Presenter, а оттуда в `IWeatherService` |
| `Core/Bootstrap/CoreScope` | DI-регистрация всех фич |
| `Tests/EditMode` | Тесты углов, ветра, машины состояний границы и погоды |

Поток данных: **ввод → InputHandler → Service → Model (R3) → Presenter → View**. View ничего не решает и не знает моделей. Сервисы не знают сцену. Связи задаются через DI, без `Find` и поиска по именам в рантайме. Кадр обновляет один `GameLoop` в три фазы: ввод → симуляция → отображение.

Почему так:
- **Логика в Core без Unity** → граница, углы и погода тестируются обычными юнит-тестами, без сцены и Play Mode.
- **Узкие порты** (`IReadOnly*Model` для чтения, `I*Service` для команд, `I*Events` для фактов) → никто не может изменить чужое состояние в обход владельца.
- **Inspector как источник ввода** → `WindInspectorInput` устроен как адаптер клавиатуры: замечает изменение и передаёт команду. Если заменить его на UI-слайдер или сервер погоды, ядро не изменится.
- **Невалидные конфиги** (не задан пресет, отрицательный радиус и т. п.) → типизированное исключение при старте сцены, а не тихая ошибка в рантайме.

## Что бы я изменил в большой игре

- **Время.** Перевёл бы таймер границы на общий сервис игрового времени: пауза, замедление, сетевой tick. Сейчас таймер останавливается вместе с `Time.timeScale`.
- **Граница.** Сделал бы форму зоны интерфейсом (`IBoundaryShape`: круг, полигон, сплайн) и добавил гистерезис на краю, чтобы предупреждение не мигало, когда корабль идёт вдоль линии.
- **Событие выхода.** `LocationExited` вёл бы к реальному переходу между локациями через загрузчик сцен с сохранением состояния корабля.
- **Ветер.** Сделал бы ветер полем: зависимость от позиции и порывы через шум. Пресеты погоды менял бы плавно, с интерполяцией за N секунд, а не мгновенно. Источником погоды служил бы сервер или расписание, а не Inspector.
- **UI.** Добавил бы локализацию строк и спрайтовый компас вместо стрелки из примитивов. Отладочные поля Inspector спрятал бы за debug-флагом.
